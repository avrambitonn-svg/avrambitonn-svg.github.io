# ג'נאייר — מערכת ניהול תפעול (גרסת הדגמה)

מערכת ניהול לחברת מיזוג אוויר, בנויה לפי שפת המותג של ג'נאייר (GENAIR, SMART AIR CONDITIONING): תכלת `#00aeef`, אפור כהה `#1c2127`, גופן Assistant, עברית מימין לשמאל.
המערכת מכסה את כל מה שהוצג בפוסט של בני ביטון (פתיחת קריאה בשטח, הצעת מחיר בעזרת AI מתמונה, תיאום מתקינים, סגירה, סנכרון ל-Priority, Drive, וואטסאפ, יומן גוגל, התראות והרשאות לפי תפקיד), ומוסיפה עליו את מה שחסר לעסק כמו ג'נאייר: שירות ותחזוקה, אחריות, פרויקטים של יזמים, פורטל לקוח וחתימה דיגיטלית.

> בלי שרת המערכת רצה כהדגמה: הנתונים בדויים ונשמרים בדפדפן. עם השרת (`server/`) יש התחברות, מסד נתונים משותף לכל העובדים, וסנכרון בזמן אמת.

**תפקידים:** ניהול, משרד, סוכן מכירות, מהנדס, מתקין. כל תפקיד רואה רק את מה שרלוונטי לו (מתקין נכנס ישר לאפליקציית השטח). בהדגמה מחליפים תפקיד מהבורר "צפייה בתור" בראש המסך; עם השרת כל עובד נכנס עם סיסמה.

## מה נוסף מעבר למה שהוצג בפוסט

- פורטל לקוח עם חתימה דיגיטלית, במקום לשלוח PDF ולחכות לתשובה.
- שירות אחרי מכירה: אחריות לפי מספר סידורי, קריאות שירות, חוזי תחזוקה ותזכורות שנתיות.
- פרויקטים של יזמים בבנייה רוויה (חלק גדול מהעבודה של ג'נאייר), כולל שדרוגים לדיירים.
- תכנון לפי שבתות וחגים, ומזג אוויר לעבודות חוץ ועבודה בגובה.
- תוקף הסמכות של מתקינים, והתראה לפני שפג.
- רווחיות ועמלות סוכן, מקדמה בעת אישור.
- עבודה מהנייד כאפליקציה (PWA), כולל כשאין קליטה.
- בקשת ביקורת בגוגל אוטומטית בסיום התקנה.

## חיבורים

### עובדים בלי שום הגדרה

וואטסאפ בלחיצה (`wa.me`), ניווט ב-Waze ובגוגל מפות, הוספה ליומן גוגל וקובץ ICS, זמני שבת וחגים (Hebcal), מזג אוויר (Open-Meteo), הכתבה קולית בעברית, קודי QR, שיתוף מהנייד, טופס פנייה להטמעה, והתקנה כאפליקציה.

### דורשים את שרת האינטגרציות (`server/`)

המפתחות נשמרים רק בשרת. מגדירים את כתובת השרת בהגדרות ← חיבורים.

| חיבור | מה צריך |
|---|---|
| Priority | כתובת השרת של הלקוח, משתמש API, ו-App ID/App Key מ-Priority. **הרישיון שייך ללקוח** ונקנה דרך השותף שלו. כתיבה חסומה עד `PRIORITY_ALLOW_WRITE=true` |
| AI (Claude) | `ANTHROPIC_API_KEY`. בלי מפתח ההצעה נבנית במנוע מקומי פשוט (לפי שטח וחשיפה) כדי שאפשר יהיה לראות את התהליך |
| WhatsApp Business API | מספר מאומת ב-Meta, Access Token, ותבניות הודעה מאושרות. בלי זה ההודעות נשלחות בלחיצה |
| Google Calendar ו-Drive | חשבון שירות עם גישה ליומן ולתיקייה. בלי זה יש קישורי "הוספה ליומן" |

פירוט מלא, נקודות קצה ומיפוי השדות ל-Priority: [server/README.md](server/README.md), [server/PRIORITY_MAPPING.md](server/PRIORITY_MAPPING.md).

## הרצה מקומית

```bash
# האפליקציה
cd genair/app
npm install
npm run dev          # http://localhost:5173

# שרת האינטגרציות (Node 22, בלי תלויות)
cd genair/server
cp .env.example .env
npm start            # http://localhost:8787 — בלי הגדרות נוספות הוא מחובר לסביבת הדמו של Priority (קריאה בלבד)
npm test
```

אחר כך בהגדרות ← חיבורים: כתובת השרת `http://localhost:8787`, ולסמן את Priority.

## פריסה

- **האפליקציה** היא אתר סטטי: `npm run build` יוצר את `app/dist`, שאפשר להעלות לכל אחסון סטטי (Vercel, Netlify, Cloudflare Pages, GitHub Pages). עם שרת: לבנות עם `VITE_SERVER_URL=https://<השרת>`.
- **קובץ אחד**: `npm run build:single` יוצר את `app/dist-single/index.html`, כל המערכת בקובץ אחד שנפתח בלחיצה כפולה, בלי שרת. נוח לשלוח ללקוח לצפייה.
- **הדגמה בלי שם החברה**: `VITE_BRAND=demo npx vite build` בונה את אותה מערכת עם מותג ניטרלי (בלי שם, טלפון וכתובת של ג'נאייר), והתפריט של ההדגמה נפתח מיד.
- **השרת** (אינטגרציות, מסד נתונים משותף והתחברות): Docker, Render, Railway/Fly.io או כל שרת Node. פירוט ב-[server/README.md](server/README.md).

הריפו הזה הוא יעד הבנייה של אתר הקורס במתמטיקה, והקבצים בו נדרסים בכל בנייה. כדאי להעביר את `genair/` לריפו נפרד לפני שממשיכים.

## מגבלות ההדגמה

- בלי שרת, הנתונים נשמרים בדפדפן (IndexedDB): משתמשים שונים לא רואים את אותם נתונים, ופורטל הלקוח עובד רק באותו דפדפן. עם השרת זה משותף.
- נתוני ההדגמה כוללים היסטוריה בדויה מינואר בשנה שעברה ועד היום, כדי שהדשבורד והדוחות ייראו כמו בעסק פעיל.
- תשלום המקדמה מדומה.
- סביבת הדמו של Priority משותפת לכולם, ולכן השרת לא כותב אליה.

## מה צריך לייצור

1. להריץ את השרת עם דיסק קבוע וגיבוי (המסד הנוכחי הוא קובץ JSON; למעבר ל-Postgres מחליפים רק את `src/db/adapters.js`).
2. רישיון API ל-Priority מהלקוח, ובדיקת המיפוי מול הטבלאות שלו (קודי פריטים, מחירונים, סוכנים).
3. ספק סליקה ישראלי למקדמה (קישור תשלום או Bit).
4. אישור תבניות וואטסאפ ב-Meta.
5. גיבויים, ניטור שגיאות ותיעוד פעולות לפי משתמש.
